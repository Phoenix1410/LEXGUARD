# Bugfix Requirements Document

## Introduction

The LEXGUARD application has a distributed backend architecture issue where the AI analysis functionality (explanation field) is missing from `/analyze_document` endpoint responses when deployed. The frontend correctly receives clause detection results from the ML models (Sniper and Scout), but the ChatGroq-powered AI explanations generated by the `process_analyst_evaluation` function are not being returned. This occurs because the frontend's `NEXT_PUBLIC_API_URL` environment variable points to `http://localhost:8000` (a basic Docker backend without AI capabilities) instead of the HuggingFace Spaces deployment (port 7860) that contains the complete AI analysis stack including GROQ_API_KEY and ChatGroq analyst.

## Bug Analysis

### Current Behavior (Defect)

1.1 WHEN the frontend is deployed on Vercel and calls `/analyze_document` THEN the system returns analysis results with empty or missing `explanation` fields in the response

1.2 WHEN `NEXT_PUBLIC_API_URL` is set to `http://localhost:8000` in production THEN the system routes API calls to a backend without GROQ_API_KEY or ChatGroq functionality

1.3 WHEN the Docker backend (port 8000) receives `/analyze_document` requests THEN the system fails to execute `process_analyst_evaluation` function properly due to missing AI dependencies

1.4 WHEN HuggingFace Spaces deployment (port 7860) contains the complete AI stack THEN the system is not being utilized for production API calls

### Expected Behavior (Correct)

2.1 WHEN the frontend is deployed on Vercel and calls `/analyze_document` THEN the system SHALL return complete analysis results with AI-generated explanations in all flagged clause objects

2.2 WHEN `NEXT_PUBLIC_API_URL` is configured for production deployment THEN the system SHALL route API calls to the HuggingFace Spaces backend with full AI capabilities

2.3 WHEN the production backend receives `/analyze_document` requests THEN the system SHALL successfully execute `process_analyst_evaluation` with ChatGroq analyst and return detailed explanations

2.4 WHEN environment configuration is properly set for deployment THEN the system SHALL consistently use the backend instance that contains GROQ_API_KEY and AI models

### Unchanged Behavior (Regression Prevention)

3.1 WHEN running in local development mode THEN the system SHALL CONTINUE TO work with `http://localhost:8000` for developer convenience

3.2 WHEN the Sniper model (DistilRoBERTa) processes clauses THEN the system SHALL CONTINUE TO detect and classify risk types correctly

3.3 WHEN the Scout model performs semantic search THEN the system SHALL CONTINUE TO match user rules and identify relevant clauses

3.4 WHEN authentication and file upload functionality is used THEN the system SHALL CONTINUE TO work properly across all backend configurations

3.5 WHEN other API endpoints like `/users/sync` and `/compare_testimonies` are called THEN the system SHALL CONTINUE TO function normally
